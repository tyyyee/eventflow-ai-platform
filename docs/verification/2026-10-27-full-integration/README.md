## HTTP 对照结果

8 个工作线程、17 个真实会话，每次请求后等待 25ms；每模式三轮，每轮 10 秒，交替顺序。共 **8942 次请求，稳定阶段 HTTP 错误 0、响应核对差异 0**。结果核对包含完整列表、总数、状态及用户归属。

| 模式 | 三轮完成请求/秒中位数 | 三轮 P95 中位数 |
|---|---:|---:|
| LOCAL | 160.96 | 31.53ms |
| SHARDED | 134.04 | 71.80ms |

数据来自少量真实接口创建的测试订单，源库也保留之前失败尝试的合法测试订单。这不是百万订单接口实验，也不是最大吞吐测试；吞吐包含刻意等待。该小数据场景下，跨实例路由有额外开销，未观察到性能提升，简历不写提升比例。

P95 包含 HTTP、Cookie 数据库会话鉴权、入口读模式查询、SQL、JSON 与客户端核对。原始 CSV 留在 `.local/integration`，[独立复算脚本](../../../backend/scripts/integration-report.mjs)核对样本数、P95、完成请求/秒并生成 SHA-256。见[逐轮表](http-table.md)与[复算摘要](http-summary.json)。故障阶段的预期 503 和稳定阶段错误率分别记录。

此前百万级合成数据是独立 schema 中的 JDBC 对照，仍以[前轮记录](../2026-10-27-sharding/README.md)为准，两组数据不能拼接成百万订单下的 HTTP 性能结论。

## 变更与原有测试

新增本机运行、完整 HTTP 验收、数据复算和隔离回归脚本，以及复现说明与简历补充。修复一处应用配置：只提供 `APP_AUTH_SECRET` 时，未定义的旧备用变量仍会触发嵌套占位符解析失败；补空缺省值后继续由 Auth 的最小长度校验阻止无密钥启动。新增两项配置测试，覆盖首选变量、旧变量、优先级和未配置时拒绝。

原有 `Trading`、`Payments`、`DelayedClose`、`ShopCache`、`OrderProjection` 的 SHA-256 均与分片改造前一致，见[原实现核对](unchanged-core.json)。没有修改缓存策略、库存规则、建单语义、支付和关单规则，也未修改历史 migration。

完整回归共 158 项：**145 项通过、13 项按条件跳过、0 失败/错误**。使用独立 schema、Redis DB13、独立 Kafka topic/group，原有中间件及客户 HTTP 的 49 项外部测试全部启用并通过，结果见 [test-summary.json](test-summary.json)。13 项跳过为分片实验的环境、路由、外部同步、迁移、基准及清理条件测试；这些已在前轮单独执行，本轮不重复灌入大型数据。

## 失败记录与修正

本轮不是一次执行即成功，保留了以下失败，未将它们计入最终稳定对照：

1. 最初运行包因嵌套密钥占位符导致启动失败。修复配置并通过新增测试、打包及实际运行验证。
2. Windows 中后台 Java 子进程持有父进程输出管道，导致验收脚本等待。改为丢弃生命周期子命令的输出，组件继续写各自文件。原始记录在 `.local/failures/03-integration-service-pipe`。
3. 后端重启时，Redis 连接初始化偶发超过原 300ms 超时。启动脚本改为检查 readiness、最多三次启动并保存前次日志；没有放宽应用超时。失败记录在 `.local/failures/04-integration-redis-startup`。
4. Redis 健康检查恢复后，业务连接仍处于重连窗口，立即创建 fixture 收到 503。修正验收前提：事先准备活动，恢复阶段使用同请求键有界重试，并独立记录预期 503 和恢复耗时；对应记录在 `.local/failures/05-integration-reconnect-window`。

## 环境及实际边界

- 实测：三个独立 MySQL 8.0.31 实例、Windows Redis 3.2.100、Kafka 3.9.0/KRaft、JDK 17.0.3.1。版本、实例 UUID、运行包 SHA-256 见 [runtime.json](runtime.json)。系统 3306 未参与。
- 本机无 Docker，Compose 声明的 MySQL 8.4、Redis 7.4、Kafka 3.9.1 组合未启动；本机旧 Redis 的兼容性结果不替代该容器组合的验收。
- 客户操作使用实际注册登录会话。管理入口使用已有实验 HMAC；后端只绑定本机并启用 benchmark 管理能力，不是生产管理员体系验收。
- 付款为本地模拟，不涉及真实资金。没有浏览器 UI 重测、真实大模型效果测试或新 Agent 功能。
- 同步和恢复耗时为单次观测，含轮询及脚本开销，没有生产 SLA 含义。
