# 校园抢票前端体验优化验证

日期：2026-10-11（Asia/Shanghai）

## 参考依据

本轮参考公开产品介绍和帮助中心中的交互方式；未登录这些平台，也未进行真实购票。

| 参考产品 | 可借鉴的体验 | 本项目采用的方式 |
| --- | --- | --- |
| [Eventbrite App](https://www.eventbrite.com/consumer/eventbrite-app/) | 发现、收藏和票夹分开；活动关键详情突出 | 保留活动与票夹，新增收藏入口，活动卡片突出日期、校区与票档 |
| [Eventbrite 使用说明](https://www.eventbrite.co.uk/help/en-au/articles/783059/how-to-use-the-eventbrite-iphone-app/) | 分类、价格等筛选，活动爱心收藏 | 保留现有分类、校区和排序；展示当前筛选条件，支持逐项删除与一键清空 |
| [Fever 官方 App 介绍](https://play.google.com/store/apps/details?hl=en_GB&id=com.feverup.fever) | 筛选与收藏用于活动发现 | 独立收藏页、空状态、跨浏览器标签同步 |
| [DICE 候补说明](https://dicefm.zendesk.com/hc/en-gb/articles/4409669441169-Buy-tickets-to-a-sold-out-event-via-the-wait-list) | 售罄后仍有候补入口，展示排队与补位结果 | 继续使用项目已有的候补链路；在发现页说明候补能力，在票夹查看结果 |
| [大麦功能说明](https://help.damai.cn/helpPage.htm?pageId=17) | 分类和演出日历帮助用户找活动 | 分类入口分色，卡片显示活动日期与下一场时间 |

以上是对适用交互方式的选择，不表示复制上述产品，也不表示本项目实现了它们的全部功能。

## 本轮改动

- 新增独立收藏页；卡片和详情均支持收藏。收藏保存在当前浏览器，不是服务端账号收藏。
- 收藏刷新后保留，同一浏览器内多个标签同步；保存失败给出明确提示；最多保存 50 场。
- 活动卡片优先展示日期、分类、校区、余票和价格；手机上的标题可显示两行，时间信息继续保留。
- 筛选条件以可删除标签展示；空结果提供一键重置，重置时回到第一页。
- 活动详情固定标题与关闭入口，底部提供“选择票档”跳转；关闭后焦点回到原活动卡片。
- 抢票按钮区分尚未开售、已结束和正在提交；详情失败时可直接重试。
- 视图切换保存浏览位置，返回活动页后继续浏览原位置。
- 手机底部导航为活动、收藏、规划、票夹；考虑安全区和减少动画设置。
- 演出示意图改为舞台与麦克风，移除容易被误认为视频播放入口的三角图案。

支付接口、库存扣减、异步建单及关单补偿逻辑没有改动。

## 验证环境与结果

前端 `http://127.0.0.1:4178`，后端端口 8093；使用现有本地 MySQL、Redis 和 Kafka。模拟支付开启；规划使用 `PLANNING_MODE=stub`，未调用外部模型。

| 验证 | 结果 |
| --- | --- |
| `npm run build` | 通过 |
| `npm run test:e2e` | 9 组通过，无浏览器运行异常 |
| `npm run test:payments` | 5 项通过 |
| `npm run test:discovery` | 6 组通过，涵盖 320、390、768、1440 像素 |
| `git diff --check` | 通过 |

### 体验检查

1. 收藏空状态、保存与刷新恢复；收藏按钮不会触发活动详情。
2. 同一浏览器的两个标签间同步收藏。
3. 空查询清除筛选、分类删除与分页重置。
4. 四种宽度无页面横向溢出、无按钮内容溢出；详情跳转票档、Escape 关闭并恢复焦点。
5. 浏览器存储不可写时显示失败，没有假称收藏成功。
6. 切换视图时恢复活动列表的浏览位置。

### 业务回归

原有 9 组流程包含注册、会话恢复、真实异步建单、模拟支付、取消、每人一次限制、丢失请求响应后的原请求恢复、账号隔离、手机布局，以及规划演示。

已有支付 5 项检查包括响应丢失后轮询恢复、刷新后保留支付结果、历史订单和手机布局、取消后到账自动退款、重新查看退款记录。

回归脚本现在同时支持“确认出票”模式和“模拟支付”模式。

## 复现

启动已有本地依赖后：

```sh
PLANNING_MODE=stub DEV_PORT=4178 bash run.sh dev
```

在 frontend 目录运行测试，使用已安装的 Playwright 与 Chrome：

```sh
LIFE_URL=http://127.0.0.1:4178 LIFE_BROWSER_CHANNEL=chrome npm run test:e2e
LIFE_URL=http://127.0.0.1:4178 npm run test:discovery
LIFE_URL=http://127.0.0.1:4178 npm run test:payments
```

如果 Playwright 不在默认依赖位置，可设置 `PLAYWRIGHT_MODULE` 为本机已有模块的绝对路径。截图和完整结果默认保存在 `frontend/test-output/`，该目录已加入 Git 忽略规则。

## 适用范围

这是本地演示环境的功能与布局验证，尚未进行真实用户可用性测试；没有测量转化率或满意度提升。收藏快照里的余票和价格可能过时，打开详情时会重新读取后端数据，提交抢票时继续校验实时库存。
