# 第一期：智能票务助手与轻量 Harness

实现目录为 `加了agent之后的内容`。本期围绕“找活动 → 调整条件 → 查当前余票 → 打开原购票入口”，增加已发布规则查询和本人订单查询。Agent 不修改交易数据；库存、限购、建单、支付和关单仍由原业务服务裁决。

## 直接体验

Windows PowerShell 7，在项目根目录运行：

```powershell
./backend/scripts/assistant-local.ps1 start
```

打开 `http://127.0.0.1:4286`，点击顶部“助手”，注册专用演示账号。

按顺序输入：

1. `明天预算100元，推荐音乐活动`
2. `换成主校区的，其他条件不变`
3. `第一个还有票吗？`
4. `购票有什么规则？`
5. 在卡片中打开活动详情，自行确认抢票后，再问 `看看我的抢票结果`。

“太贵了，便宜一点”会保留其他条件，以选中活动价格为参考进一步降低价格上限。未选中活动时，参考上一轮最低价；不会偷偷放宽预算或改校区。“预算不限”可以明确移除预算条件。

本地演示以中文日期、数字预算、校区、常见分类和序号等有限表达为例；复杂自由表达应切换真实模型后单独评测。演示没有 LLM 推理，不产生真实模型调用及 token 成绩。

脚本 `status` 查看服务，`stop-backend` 只停前后端，`stop` 停本环境全部服务。脚本只领取自己保存且命令行匹配项目目录或专属运行目录的进程，不接管其他实例。MySQL/Redis/RocketMQ 使用系统临时目录下按项目路径哈希隔离的 `qupiao-assistant-*`，凭据和进程信息保存在 `.local/assistant`，不提交版本库、不打印密码。端口为 MySQL 34307、Redis 37380、NameServer 40876、Broker 40911、后端 8193、前端 4286。

启动前需本机 Java 17、MySQL 8、Redis、Node、已安装前端依赖和打包后的后端。脚本参数可以调整软件安装路径，RocketMQ 复用本目录 `.local/rocketmq/distribution` 中已验证的 5.3.2 分发包。环境的旧 V15 迁移含触发器，独立 MySQL 配置已设置 `log-bin-trust-function-creators=1`；应用账号仅有两个助手数据库的权限。

## 两种运行模式

默认配置：

```text
ASSISTANT_MODE=stub
ASSISTANT_JOBS=true
```

真实模型配置只填入本机环境或未提交的 `.env`，不要写入源码：

```text
ASSISTANT_MODE=deepseek
DEEPSEEK_API_KEY=自行配置
DEEPSEEK_BASE_URL=https://api.deepseek.com
ASSISTANT_MODEL=deepseek-flash
```

随后重启后端。Windows 脚本使用 `start-backend -Mode deepseek`；运行前必须设置密钥环境变量。配置错误或模型不可用时返回失败，不会悄悄切换成本地演示。`ASSISTANT_MODE=disabled` 关闭新对话执行。

实现遵循 [DeepSeek 原生工具调用协议](https://api-docs.deepseek.com/guides/tool_calls/)，使用 `tools`、`tool_calls` 和 `tool_call_id`，关闭思考模式，不保存隐藏推理。普通文本回答不直接用作票价、余票、订单或退款事实；前端答案、规则和卡片由业务查询结果生成。

## Agent 与 Harness 分工

真实模型判断意图、选择工具、补充缺少的信息，并根据查询结果决定是否继续。Java Harness 负责工具白名单、参数校验、登录身份、预算、持久化、恢复和输出。

| 工具 | 功能 | 约束 |
| --- | --- | --- |
| `search_activities` | 按条件搜索已关联的活动场次 | 参数只修改指定条件；清空需显式 null；按时间或价格排序，最多展示8项 |
| `get_activity` | 重新查询候选活动的价格、余票和开售窗口 | 只接受已展示候选或选中活动；序号基于最近展示的活动列表 |
| `get_rules` | 查询共同购票规则和具体活动须知 | 引用已发布内容；未列出的退改细节不推测 |
| `get_my_orders` | 查询本人最近请求、订单 | 登录用户由服务端注入，最多展示10条 |
| `get_my_order` | 按请求编号查询本人记录 | 同时校验用户归属；其他人的编号统一返回未找到 |
| `ask_clarification` | 请求补充时间、预算、校区或目标 | 只允许预定义追问类型，结束本轮执行 |

工具没有 SQL、HTTP URL、Shell 或任意写库入口。模型传入 `userId`、未知参数或未知工具会被拒绝。独立只读订单适配不会触发原查询接口里的超时关单操作。CORE32 构建提供分片查询适配，按认证用户路由；本轮真实联调使用单库模式，未运行新的四库端到端测量。

## 活动与余票的数据来源

V17 给 `ux_experience_session` 增加可空的 `activity_id` 外键与唯一索引。场次必须显式关联实际可购买活动，并且对应发布的场馆和售票记录，才进入推荐。已有未关联数据不会靠名称或商家 ID 自动猜测匹配关系。

演示数据生成器为当前演示场次写入关联。正式数据需要由维护者确认时间、购买入口及其对应关系后填入 `activity_id`。原 `planning` 功能仍可独立使用。

活动时间来自 `ux_experience_session`；价格、数据库余票和开售窗口来自 `ux_activity`，忽略规划表中的影子价格和余票。规则来自平台版本化代码及已发布的 `ux_offer.terms`、`ux_storefront.service_notice`。支付状态只解释已查询到的订单，不凭订单关闭就断言退款成功。

余票是查询时的数据库快照。Redis 中尚未落库的预占及后续并发请求都可能影响实际受理；展示有余票不保证抢票成功，也不代表占位。打开卡片会重新进入原详情页，提交时继续执行原 Redis Lua、数据库约束及异步建单。

检索使用上海时区，默认查询近期30天，可指定不超过31天的日期范围。为限制数据库读取，最多扫描1000条候选；达到扫描上限又无法确定结果时，要求缩小范围，不伪称“没有匹配活动”。

## 会话、任务与恢复

- `ux_assistant_session`：用户、结构化条件、最近候选、选中活动、最近6条用户及助手文本和当前任务；这些文本按条数截取，不是额外模型生成的摘要。
- `ux_assistant_run`：原问题、幂等请求标识、执行模式、状态、期限、租约、检查点和结果。
- `ux_assistant_step`：工具、参数、结果、耗时与执行结果。对外步骤接口只返回工具名、状态和耗时，不返回原始参数及订单数据。
- `ux_assistant_quota`：短事务序列化入队配额检查。模型调用不持有数据库事务或订单行锁。

同一个会话和 `requestKey` 重试会返回原任务；换内容沿用旧 key 返回冲突。每用户同时执行一条任务，全局待处理与执行中任务上限100。每用户每分钟最多10条新问题、50段会话，每段最多40轮；用完可删除旧对话或新建对话。

任务异步执行，前端提交后查询进度。实例最多2个工作线程；单任务总期限60秒、最多5次决策与8次工具调度。累计模型用量达到12,000 tokens后停止，单次请求最多生成1000 tokens。tokens 按供应商返回量统计，反馈后才可知道实际用量，不是精确的账单硬上限。演示模式 `modelCalls=0`、`totalTokens=0`。

任务领取有30秒租约，模型结果与每次工具结果都会持久化并续租。步骤记录与检查点同事务提交。进程中断后，其他工作线程可以在租约到期后继续尚未完成的只读步骤；已完成步骤不重新执行。跨轮余票仍须重查。

如果中断时供应商调用仍未确认结果，或用量缺失，任务以“用量未知”失败收口，不自动再次调用模型。超过总期限会标记超时并释放会话，旧工作线程不能覆盖新持有者或超时结果。因此恢复不等于每个任务都必然成功。

查询出现短暂数据库错误可有限重试；工具执行失败不会渲染缓存中的旧结果来伪装成功。前端先在浏览器会话存储中保存问题及原 key，发送响应丢失后仍用原 key 重试；刷新、切换账号和多实例均以服务端归属校验为准。

真实模型扩展评测后增加三项约束：首个搜索条件保存到本轮检查点，后续调用不能偷偷更改；同轮订单详情按请求ID合并，不覆盖已查订单列表；补充规则时保留本轮活动卡片，组合结果采用最早证据时间。新一轮用户可明确修改筛选条件。评测与修复记录见[Agent效果评测](../verification/2026-11-09-assistant-evaluation/README.md)。

## 接口

所有接口需要既有登录态；写入会话或提问还需要 CSRF。

```text
GET    /v2/assistant/sessions
POST   /v2/assistant/sessions
GET    /v2/assistant/sessions/{sessionId}
DELETE /v2/assistant/sessions/{sessionId}
POST   /v2/assistant/sessions/{sessionId}/turns
GET    /v2/assistant/sessions/{sessionId}/turns/{runId}
GET    /v2/assistant/sessions/{sessionId}/turns/{runId}/steps
GET    /v2/assistant/policy
```

提问请求：`{"requestKey":"客户端稳定请求标识","message":"明天预算100元，推荐音乐活动"}`。提交返回202及任务标识；完成后返回结构化 `reply`，其中包括回答类型、活动、规则、本人订单、查询依据和时间。

验收范围、执行结果与截图见[验收记录](../verification/2026-11-09-assistant/README.md)。
