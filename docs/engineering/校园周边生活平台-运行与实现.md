# 趣生活：运行与实现

2026-11-20 已继续升级真实摄影、多轮对话和账号偏好；DeepSeek 自动配置方法见[最新说明](真实照片与个性化生活助手.md)。以下保留首版接口与运行基础。

本轮把原校园票务项目扩展为校园周边生活平台。新商铺、免费券和社区使用独立业务表，原活动、票档、订单、RocketMQ 和 Outbox 链路保留。产品规则见 [PRD](../product/校园周边生活平台-PRD.md)，独立评审最终为 **94/100，通过**，见 [评审记录](../product/校园周边生活平台-PRD评审.md)。

## 已实现的用户流程

- 首页：搜索、六种分类、三个校区、商圈、人均预算、评分、营业状态、可领券和距离筛选；选择六个校园地标，或主动授权浏览器定位。距离为直线距离。
- 店铺：介绍、营业时间、图片相册、评价评分、收藏、免费领券、探店打卡。
- 账号：注册、登录、资料、头像、改密、一次性恢复码、服务端收藏、每日签到、连续签到、自己的评价、打卡和反馈。
- 社区：发布/修改/删除评价、图片、点赞/取消点赞、举报；隐藏内容不计入公开评分，旧图片 URL 也收回公开权限。
- 免费券：领取、限领、券包、状态与适用规则快照、运营预览并核销、作废及原因。核销与作废互斥，重试保留原操作结果。
- 活动：保留抢票、处理中结果、待支付、模拟支付、取消、超时关闭、退款和候补。
- 运营：商铺、券模板、评价审核、FAQ 版本、举报、反馈、操作审计。入口 `/ops`，权限由服务端账号角色决定。
- 助手：多轮选店、比较店铺、查询优惠、本人券包、本人支付/退款、FAQ 来源和反馈草稿；反馈仍由用户确认提交。

首版不连接真实支付、短信、地图商家数据、外卖配送。商铺、人物、地点和样例评价均为虚构；页面已标注。领券不收费，也不抵扣活动门票。

## Windows 本地启动

使用 PowerShell 7.2+、Java 17、Maven、Node.js 22+，以及已有的 MySQL、Redis、RocketMQ 5.3.2 分发包。在项目根目录执行：

```powershell
$env:JAVA_HOME='F:\Java17\JDK 17'
cd backend
# Maven 未加入 PATH 时可使用现有 Maven 的绝对路径。
mvn -DskipTests package
cd ../frontend
npm ci
npm run build
cd ..
./backend/scripts/local-life.ps1 start
```

脚本可用 `-JavaHome`、`-MysqlHome`、`-RedisHome`、`-RocketMqHome` 指定安装位置。默认 RocketMQ 位于 `.local/rocketmq/distribution/rocketmq-all-5.3.2-bin-release`。脚本创建单独运行目录与数据库，不使用原 assistant-local 的端口。启动时检查后台就绪状态。

| 服务 | 本地地址/端口 |
| --- | --- |
| 页面 | http://127.0.0.1:4386 |
| 后端 | 127.0.0.1:8293 |
| MySQL | 127.0.0.1:44307，`qulife_local` |
| Redis | 127.0.0.1:47380 |
| RocketMQ | nameserver 50876，broker 50911 |

脚本首次生成 `.local/local-life/credentials.json`，该文件被 Git 忽略。`demoPassword` 对应普通演示账号 `campus_demo`、`campus_friend`，`operatorPassword` 对应运营账号 `campus_operator`。请在本机查看，勿上传该文件。也可直接注册自己的测试账号。

```powershell
./backend/scripts/local-life.ps1 status
./backend/scripts/local-life.ps1 stop-backend
# 更改 Java 代码后先停后端，再打包，避免 Windows 文件占用。
./backend/scripts/local-life.ps1 start-backend
./backend/scripts/local-life.ps1 stop
```

本地数据保存在该项目专用的临时运行目录，路径由项目绝对路径哈希计算；密钥和进程记录在项目 `.local/local-life`。移动项目后会使用新的独立运行目录。它用于开发演示，正式部署请使用持久化数据库和备份。

## 配置和兼容边界

默认 `LOCAL_LIFE_ENABLED=false`，继续展示原票务页面；开启后使用趣生活页面。`LOCAL_LIFE_DEMO=true` 才写入新样例。两者均由 local-life 脚本显式开启。

`LOCAL_LIFE_ENABLED=true` 与 `CORE32_ENABLED=true` 不能同时使用，启动时拒绝此组合。新模块仅验收单库；原 CORE32 源码与文档保留，不据此宣称新社区和券包已适配分库。

`V18__campus_local_life.sql` 为增量迁移。真实商铺使用新增的 `ux_local_shop` 资料，展示基础字段沿用 `ux_shop`；原活动 ID 不改。种子 30 家商铺、180 条样例评价、20 个虚构评价用户、30 条 FAQ、20 个当日券模板，使用唯一 seed key 防重；重启不恢复消耗库存、不覆盖运营修改。旧票务种子与新商铺种子相互独立。

上传目录由 `LOCAL_LIFE_MEDIA` 配置，默认 `.local/local-life-media`。每图最大 5 MB、最大边 8000 像素、最大 2000 万像素；服务器解码重编码 JPEG，清除 EXIF，生成缩略图。每账号每天最多 50 次、累计 200 MB。图片绑定用途与拥有者；未关联上传 24 小时后清理。公开内容隐藏后旧 URL 不再公开，媒体响应禁用共享缓存。

Docker Compose 可在 `.env` 中开启 `LOCAL_LIFE_ENABLED=true`、`LOCAL_LIFE_DEMO=true`，填写演示账号密码并选择 `SANDBOX_PAYMENTS=true` 后重新构建。媒体使用 `local-media` 卷。此次实际运行验证使用 Windows 原生中间件，未把 Compose 配置检查等同于容器运行验收。

## 关键数据与并发规则

| 功能 | 数据和处理方式 |
| --- | --- |
| 改密/恢复 | 密码 BCrypt；恢复码只存摘要、单次使用；账号行锁协调改密和登录，改密成功后撤销旧会话 |
| 收藏/签到/点赞 | 服务端用户标识、组合唯一约束、重复写幂等；签到日按 Asia/Shanghai |
| 评价 | 同一用户/商铺最多一条未删除评价；版本号防并发覆盖；统计只计算已发布评价 |
| 领券 | 用户与模板锁、剩余量条件扣减、用户/模板唯一；领取时复制金额、时间和规则 |
| 核销/作废 | 同一张券行锁协调，状态条件变更；运营操作键持久化请求摘要和原结果；同键不同参数拒绝 |
| 商铺变更 | 版本号检查；事务内登记 Bloom 新 ID，写缓存失效任务；不绕过既有缓存机制 |
| 付款/关单 | 使用已有票务交易、CAS、Outbox 和补偿，不把免费券混入门票库存 |

核销、作废、过期均不恢复模板可领取数量。券核销码只在本人详情/运营核销场景显示，不进入券包列表和助手工具结果。公开图片与商铺相册中的 SVG 是本次原创示意图，来源清单位于 `frontend/public/local-assets/manifest.json`。

## Agent 怎么工作

沿用已有持久化助手运行、检查点、工具白名单、步数/时间预算与失败恢复。新工具为：

`search_shops`、`get_shop`、`compare_shops`、`get_shop_coupons`、`get_my_coupons`、`get_my_payment_status`、`search_policies`、`prepare_support_draft`。

身份来自已认证会话，工具不能传入另一个 userId；详情/比较必须引用查询得到的候选店铺。筛选条件跨轮保留；同轮不能擅自放宽条件。总预算需要人数，服务器换算为人均上限。位置坐标只用于页面查询，不进入助手上下文。

结果卡片包含来源和查询时间。助手不能自动抢票、领券、核销、付款、取消或退款。客服不以“订单已关闭”推断“退款已完成”，而是读取本人付款和退款动作记录。反馈工具只产生草稿。

默认 `ASSISTANT_MODE=stub`，使用确定性本地演示逻辑和真实业务查询。配置真实模型需 `ASSISTANT_MODE=deepseek`、`DEEPSEEK_API_KEY`、`ASSISTANT_MODEL`。本轮没有使用模型密钥或产生模型费用；真实模型效果评测仍需在配置完成后执行。

## 常用接口

| 场景 | 接口（统一 `/v2` 前缀） |
| --- | --- |
| 能力开关 | `GET /capabilities` |
| 登录注册/恢复 | `POST /auth/login`、`/auth/register`、`/auth/recover` |
| 商铺 | `GET /local/shops`、`/local/shops/{id}` |
| 收藏 | `GET /account/favorites`，`PUT/DELETE /account/favorites/{SHOP或EVENT}/{id}` |
| 券 | `GET /local/shops/{id}/coupons`，`POST /coupons/{id}/claim`，`GET /account/coupons` |
| 评价 | `POST /local/shops/{id}/reviews`，`GET/PATCH/DELETE /reviews/{id}` |
| 签到/打卡 | `PUT /account/signs/today`，`POST /local/shops/{id}/checkins` |
| 上传 | `POST /media` multipart，`GET /media/{id}` |
| 运营 | `/ops/shops`、`/ops/coupon-templates`、`/ops/coupon-preview`、`/ops/coupon-redemptions`、`/ops/coupons/{id}/void` |
| 助手 | 保留 `/assistant/sessions` 与持久化运行接口 |

写接口使用 Cookie、CSRF 和账号绑定；不能把运营按钮隐藏当成权限校验。完整参数以 `Local*Api.java` 与实际业务校验为准。

## 验证

```powershell
# 普通单元/组件测试
cd backend
mvn test
cd ..
# 真实 MySQL / Redis / RocketMQ 测试，使用独立 verify 库
./backend/scripts/local-life.ps1 verify
# 浏览器验收需要先在 verify 模式启动页面，再用独立 Chrome context
./backend/scripts/local-life.ps1 stop-backend
./backend/scripts/local-life.ps1 start-backend -Verification
node frontend/tests/local-life-flow.mjs
```

浏览器脚本使用 Node 原生 CDP；Chrome 须提供远程调试，可用 `CHROME_CDP_URL` 指定地址。脚本创建并销毁自己的隔离会话，不读取已有网页或用户 Cookie。验收会创建测试账号、评价、商铺和订单，应仅指向隔离验收库。执行完用普通 `start-backend` 恢复演示库。

实际结果与未验证范围见 [本轮验收记录](../verification/2026-11-19-local-life/README.md)。此前压测数字属于原项目和当时环境，不能作为新平台的吞吐结论。
