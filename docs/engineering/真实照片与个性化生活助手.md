# 真实照片与个性化生活助手

2026-11-20：在趣生活首版基础上替换真实摄影、调整页面密度，并扩展可持续使用的个人偏好与客服对话。

## 图片和页面

47 张不同的真实照片来自 Unsplash 标准免费许可，包含餐食、咖啡与茶、火锅、烘焙、桌游/手作、自习空间和运动场景。30 家商铺使用不同封面，每家有 3 张场景相册。首页使用咖啡馆摄影，取代原插画。

图片在项目内提供，不依赖用户浏览时访问国外图片服务器。详情图宽 1280 像素；商铺列表和助手卡片使用 480 像素预览图。来源页、作者、许可、下载地址与文件摘要保存在 [图片清单](../../frontend/public/local-photos/manifest.json)，原始来源核验清单为同目录 `sources.json`。可用 `node frontend/scripts/download-local-photos.mjs` 重新下载已选图片。

这些照片是虚构商铺的场景配图，不是这些店的现场实拍。页面保留“场景配图”和演示数据说明。许可依据为 [Unsplash License](https://unsplash.com/license)。未使用 Unsplash+ 付费图片。

页面采用暖白背景、橙色操作按钮和摄影封面。手机首页缩短横幅，商铺改成左图右文，集中展示店名、评分、人均和距离；详情页为大图与两张辅图。助手采用偏好侧栏加对话区；手机端改为纵向，比较表可在自己的容器内横向滑动。

`V20` 只替换种子商铺原有的默认插画地址。已经上传的图片与包含用户媒体的相册保留；正常启动不恢复或覆盖运营资料。新增种子直接引用摄影目录。

## 多轮对话

对话、每轮任务、工具执行结果和候选店铺沿用现有数据库持久化。刷新页面后可以继续同一段对话。最近 6 轮对话摘要随请求提供给模型；动态的店铺、优惠券和订单数据仍重新查询。

已支持的连续流程：

1. “预算50元推荐咖啡店” → “换成东校区，其他条件不变”：只更改校区，保留预算与类别。
2. “不限校区” → “比较这几家店”：比较上一轮实际展示的候选，不接受模型编造的店铺 ID。
3. “换一批”：排除已显示的店，保留原条件；无结果时明确返回，不擅自提高预算。
4. “一共60元，推荐咖啡店” → “两个人”：第一轮保留总预算并追问人数，第二轮按人均30元查询。
5. “第一个有什么优惠券”：只读取上一轮候选的真实券模板，不自动领取。

同一轮首次接受的筛选条件由服务器固定，模型不能为了凑结果擅自放宽。已有检查点、租约、请求键、超时、调用次数和 Token 限制继续生效。

## 长期偏好

新增 `V19`、`ux_life_preference` 与账号接口：

```text
GET    /v2/account/preferences
PUT    /v2/account/preferences
DELETE /v2/account/preferences
```

保存常去校区、人均预算、出发地标、距离、喜欢的类别/标签，以及不推荐的类别/标签。偏好由服务端账号绑定，Cookie/CSRF 与版本号保护更新。可以暂停个性化或清空内容；不同账号互相隔离。

新找店对话首次查询时应用有效偏好，随后用户明确说出的条件优先。当前对话的临时条件不会自动写入长期偏好，更新偏好也不会悄悄改写当前对话。

“记住我喜欢安静的咖啡店”调用 `prepare_preferences`，只产生草稿。用户点击检查、编辑并确认后，普通账号写接口才保存。助手没有绕过确认的偏好写工具。个人中心“账号设置”和助手侧栏均可管理偏好。

推荐顺序会参考主动保存的喜欢类别和标签；预算、校区、距离、排除项用于限制候选。卡片的推荐理由来自实际筛选结果和公开字段，不编造“保证有座”“无需排队”等信息。饮食标签不是过敏原或食品安全承诺。

## 客服能力

- 查询当前账号的券包，支持可用/已用/过期/作废筛选；核销码不进入工具结果。
- 查询本人请求、订单、付款回执与退款完成记录；订单关闭不能推断退款已经完成。
- 按关键词相关性优先返回已发布 FAQ，附规则版本、查询时间和来源。
- 同一轮既查本人券包又查规则时，保留两部分依据，而不是只显示最后一个工具的结果。
- 处理不了的问题生成反馈草稿，由用户确认后提交，可在帮助中心查看处理进度。没有实现真实人工在线聊天，不会声称已有工作人员接入。
- 支持问候、能力介绍和后续追问；无法查询的事实明确说明，不把模型自由文本当成业务记录。

新增/扩展工具：`get_my_preferences`、`prepare_preferences`、`respond_help`，以及筛选版 `get_my_coupons`。原搜索、比较、店铺优惠、本人支付和反馈工具保留。券包工具最多返回20条、页面最多展示10条，并可进入完整券包查看。

## 启用 DeepSeek

保留 DeepSeek 原生工具调用，使用 [Chat Completions](https://api-docs.deepseek.com/api/create-chat-completion/) 和 [多轮会话协议](https://api-docs.deepseek.com/guides/multi_round_chat/)。默认模型 `deepseek-flash` 可配置，服务器发送自己的工具定义、历史和业务查询结果，不开放模型内置网页工具。

本次检查时，项目配置、进程/用户/机器环境中均未找到 DeepSeek 密钥。因此当前可用的是本地体验模式；真实 DeepSeek 的自由表达效果与在线调用尚未验收。

在最终项目根目录打开 PowerShell 执行：

```powershell
./backend/scripts/configure-deepseek.ps1
# 按提示输入密钥，输入内容隐藏。
./backend/scripts/local-life.ps1 stop-backend
./backend/scripts/local-life.ps1 start-backend
```

密钥只写入被 Git 忽略的 `.local/local-life/deepseek.env`，不会显示在页面或日志里。脚本默认 `-Mode auto`，有密钥自动启用 DeepSeek，否则本地演示。`-Mode stub` 可强制本地模式；`verify` 总是使用 stub，避免测试时意外产生模型调用。

可用 `./backend/scripts/configure-deepseek.ps1 -Check` 只检查是否配置，不输出密钥。`GET /v2/assistant/status` 为登录用户提供当前模式；界面明确显示 DeepSeek 或本地演示。配置文件支持 `ASSISTANT_MODEL` 与 `DEEPSEEK_BASE_URL`，默认为官方 HTTPS 地址。
