# 趣票核心业务分库分表实施清单

用户已确认以新提供的分库分表文档为准，允许改造主订单与相关交易链路。原“仅历史读模型双库32表”是前一阶段的已验收实现，不能充当本轮核心业务拆分的完成证明。

## 本轮目标

围绕数据增长、订单写入集中和后续扩展设计核心业务分片，采用ShardingSphere-JDBC、4个独立MySQL实例、每类分片表在每实例8张表，合计32个逻辑分片。按`user_id`计算`shard=user_id%32`、`db=shard/8`、`table=shard%8`。

库存需要全局裁决，不作为广播表复制修改。库存账本与订单分片跨库，使用持久化库存占用记录、分片内事务、Outbox和可重试补偿收敛；不声称仍有一个覆盖两库的本地事务。订单、请求、支付与关单任务按用户共置。小型展示配置可广播，金额裁决以库存占用时的权威快照为准。

原项目没有签到业务，不为了对应文章表名增加虚构业务。登录凭据与全局名称唯一性仍需要目录；用户业务数据、订单与查询应明确各自位置。新增用户及订单ID采用受worker约束的Snowflake，既有ID迁移时保留。
