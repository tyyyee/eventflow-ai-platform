## 使用顺序

从简历定稿确定五条亮点，再看09学习稿的完整流程与最后的背诵版本。当前主分片演示使用38193，默认常规启动仍是旧交易模式；不要同时给同一业务库运行两套交易处理器。

本机服务使用：

```powershell
./backend/scripts/core32-local.ps1 status
./backend/scripts/core32-local.ps1 run
./backend/scripts/core32-local.ps1 halt
```

run需要已有sharding构建、完成迁移初始化并处于CORE；不会自动帮旧业务停写切换。首次准备、迁移CLI、恢复和故障验收详见09学习稿。普通演示不要启用故障开关；Redis 由 integration-local 脚本管理，RocketMQ 由 rocketmq-local 脚本管理。旧38093后端在本轮已停止，新后端正常运行时不占旧端口。

## 明确的范围

- 真实业务量仍小。这是水平拆分与可靠性演练，没有线上海量增长和容量事故经历。
- 单活动权威库存锁、认证/目录源库单点仍在；分片不是主从容灾或自动扩缩容。
- 库存与订单跨库，使用持久占用和幂等补偿；不能再称同一个本地事务。
- 迁移为异步镜像和维护停写切换；回退须反向回填新主数据，目标库不可读时不能靠旧源库无损回退。
- 小型展示配置广播，动态库存不广播。ES、签到、自动在线扩容与真实资金渠道没有实现。
- 恢复/迁移有每活动或每用户家族1万条保护上限；超过上限需要分页方案。
- 240次HTTP采样仅验证少量订单的一致性，未形成单库与新主分片性能对照；连接采样也不是峰值吞吐证明。
- 本机离线备份已导出，跨机器完整恢复尚未验收；后续有新写入须重新备份。
